# Changelog

## Unreleased

### Corrected

- Correct the `rigorous_upper_witness` decimal in 18 of the 44 rows of `data/certified-results.csv` and `data/certified-results.json`, and the `interval_width` that follows from it. Those decimals had been rounded to nearest, which placed them below the exact potential at the upper witness point and therefore below a valid upper bound; they are now rounded outward. Each correction is `+1` in the final published digit. The fixed configurations, the certified lower bounds, the upper witness points, the two certifier families and the stored replay evidence are unchanged. See `docs/errata-v1.0.1.md`.

- Correct the `symmetry_or_family` prose of `n=15` and `n=16`, which described exact symmetries the published finite decimals do not have. The field is non-normative provenance prose and no bound depends on it; the exact invariance of all 44 configurations under the eight symmetries of the square is now computable with `certificate_lib.exact_square_symmetries`. See `docs/errata-v1.0.1.md`, which separates this clarification from the arithmetic correction above.

### Added

- `scripts/certificate_lib.py`: exact-rational helpers and fail-closed AST extraction of certifier constants. The certifier sources are never imported, executed, `eval`-ed or `runpy`-ed by the checking tools.
- A static entry-point check: each certifier must have exactly one `__main__` guard with no `else`, whose body is exactly `main()`, exactly one `main()`, one direct `certify()` call inside it, and the four final assertions over the certified result, the minimum leaf bound and the witness value. The allowed shape was derived from an inventory of the existing 88 certifiers. This rejects a module that prints `status: CERTIFIED` from its guard without running the proof — which the exit-code and status checks alone would have accepted.
- `certificate_lib.validate_proof_output`: one proof-output contract, shared by `verify_one.py`, `verify_all.py`, `validate_replay_output.py` and the historical and saved-replay checks. A successful run must carry exactly one `status`, `target_decimal`, `splits`, `leaf_count`, `maximum_depth` and `minimum_leaf_lower_bound_decimal` line and one upper witness value line; the target must equal the certifier `TARGET` as an exact rational, the counts must be canonical non-negative integers with at least one leaf, the minimum leaf bound must be at least the target, and the upper witness value must reproduce the exact potential at that certifier's witness point at that certifier's own printing precision. A stdout file whose entire content was `status: CERTIFIED` previously passed every exit-code, status, hash, schema and aggregate check in the replay pipeline.
- `scripts/check_frozen_corpus.py` and `data/frozen-corpus-v1.0.1.sha256`: the 531 files that carry the mathematics, pinned to the objects of `v1.0.1` (`d92992101ca45a5cd755b8d962652ab7e4329973`). `SHA256SUMS` is regenerated whenever the repository changes and therefore cannot distinguish a maintenance patch from an edit to a certifier — replacing a certifier with a proof-skipping version and updating the historical script hash, the per-job metadata, the aggregate tables and the manifest in the same change left the semantic check, the manifest verifier, the release check, the generator check, the upper-witness audit and `verify_one.py` all reporting success. Inside a Git repository the authority is the release commit, read **raw** with `git ls-tree` and `git cat-file`: the release blobs, the in-tree baseline and the working tree must all agree, so editing the baseline alongside the corpus fails. Object replacement is disabled on every read (`git --no-replace-objects`, `GIT_NO_REPLACE_OBJECTS=1`, `GIT_REPLACE_REF_BASE` dropped) and every `cat-file --batch` response is matched to the object id, type and size requested, because `git replace` otherwise serves substituted content under an unchanged commit or blob name; `refs/replace/` is enumerated and, under `--require-git-anchor`, its existence is a failure. The comparison covers file type and Git mode as well as content: the working tree is inventoried with `lstat`, so a frozen path replaced by a symlink to an identical copy, or given the executable bit, is rejected rather than read through. All 531 paths of `v1.0.1` are mode `100644`. Outside one — a release archive or an evidence snapshot — the run reports `git_anchor_unverifiable=1` rather than implying a comparison it did not make, and `--require-git-anchor` makes that a failure. See `docs/frozen-corpus.md`. It runs first in both workflows, with `fetch-depth: 0`.
- `validate_replay_output.py --expect-source-commit` and `--expect-source-clean`, used by the full-replay workflow. Local evidence comes from an uncommitted tree and is not required to be clean.
- An explicit unit-square check on every upper witness point, in the generator, the audit and the semantic consistency check. The potential at a point bounds the minimum over `[0,1]^2` only if the point is in `[0,1]^2`; nothing had checked it.
- `scripts/validate_replay_output.py`: re-derives a fresh replay's conclusion from its own files — recomputing each certifier's SHA-256, re-classifying each stdout/stderr pair, recomputing the aggregates, and requiring exactly the expected file inventory.
- A strict JSON loader that rejects duplicate object keys and `NaN`/`Infinity`, applied to the result tables, the metadata and both replay formats, plus exact field-set and type checks for the metadata and the stored replay records.
- `* -text` in `.gitattributes`. `SHA256SUMS` is verified against working-tree bytes, and a clone with `core.autocrlf` set would otherwise rewrite them; measured under `false`, `true` and `input`, with a control that proves the check can fail.
- `scripts/regenerate_certified_results.py`: the single deterministic generator for both result tables, with `--check` and `--write`. The tables are now build products, and no derived value can be hand-entered.
- `data/results-metadata.json`: the values that have no definition to compute — provenance prose, the externally submitted figure, the local-minima count, the descriptive minimum separation, and the presentation precision.
- `scripts/audit_upper_witness.py`: recomputes every upper witness value exactly and exits non-zero on any published decimal that falls below it.
- `scripts/check_semantic_consistency.py`: cross-checks the configuration set, CSV against JSON field by field as strings, the coordinate files against each other and against both certifiers, the certifier constants, the upper witness inequality, and the stored replay evidence including per-record script hashes and recomputed aggregates.
- `scripts/verifier_runner.py`: one shared success contract for the replay scripts.
- `tests/`: regression and mutation tests, including the n=15 case in both directions and single-point corruptions of the coordinates, the certifier constants, the tables and the replay evidence.
- `docs/data-schema.md` and `docs/errata-v1.0.1.md`.

### Changed

- `scripts/verify_one.py` and `scripts/verify_all.py` now share one success contract: exit code 0, no timeout, exactly one `status: CERTIFIED` line on stdout, no status declared on stderr, and no structured failure token in either stream. The previous substring search accepted output that declared a status twice, declared none, or printed a bare `CERTIFIED` token, and ignored stderr entirely, so a run that printed a success on stdout and a failure on stderr and exited 0 counted as certified. The forbidden tokens were measured against all 88 certifiers first: none of their stdout contains one and all 88 stderr files are empty, so no existing run is reclassified.
- `scripts/verify_all.py --all` now requires the discovered configurations to equal the published set exactly, checked before anything runs, and reports missing and unexpected values separately. A directory set where `n52` was replaced by `n53` still yields 88 verifiers and previously passed.
- `scripts/verify_all.py --output-dir` now requires a directory that does not exist or is empty, and records `repo_relative_script` and `script_sha256` per job plus the expected key set, full Python version, platform, UTC timestamp and Git commit and dirty state in the summary.
- `check_semantic_consistency.py` checks the full replay CSV for header, column order, duplicate keys and the exact expected key set — duplicating one row and dropping another kept the row count at 88 and was previously accepted — checks stored stderr for contradicting statuses, and reports unexpected or missing files in the evidence directories.
- Both result tables are written through a temporary file and `os.replace`, so neither can be left partially written. The pair is still not atomic, which `docs/data-schema.md` states rather than implies.
- The `certifier_assertions_verified` counter is renamed `certifier_module_assertions_evaluated`: it counts the module-level and helper assertions the AST evaluator actually evaluated, and never covered the final assertions inside `main()`, which are now checked structurally and counted separately.
- `scripts/validate_replay_output.py` compares every `summary.csv` cell with the corresponding `summary.json` value through a shared renderer, field by field. Checking only the header, the row count and the key set accepted a row that claimed `certified=False` with a zeroed `script_sha256` while the JSON, the per-job files and the logs all said otherwise. It also fixes the summary and record schemas exactly: unknown fields, a bool in an integer field, a duplicated `expected_keys` pair, a non-UTC timestamp, a non-hex script digest, a `worker_count` below one and a non-canonical log name are all rejected.
- `check_semantic_consistency.py` binds each historical replay record to its own log. A record must name `logs/nNN_<method>.stdout.txt` and `...stderr.txt` exactly — not merely a file that exists — and its `status`, `splits` and `maximum_depth` must be the values in that log; the logged `target_decimal` is checked against the certifier `TARGET` and the logged upper bound against the exact potential at that configuration's witness point. Previously a record could point at another configuration's stdout and carry any split count at all, and remain consistent with the aggregate JSON, the per-job metadata, the aggregate CSV, the regenerated result tables and the manifest. Per-job metadata is now read with the strict JSON loader and its field set and types are fixed.
- `verify_all.py` reads the source tree's Git provenance **before** creating the output directory and running anything, and records it as `source_git_commit` / `source_git_dirty`. An output directory inside a repository is untracked, so the previous read — taken after the logs were written — reported a clean CI checkout as dirty.
- The entry-point check is now structural rather than a count of `certify()` calls anywhere inside `main()`. `main()` must open with `<name> = certify()` as a direct, argument-free call; its second statement must evaluate the potential at that certifier's own witness point; it must contain exactly two assignments and no `return`, `raise`, `try`, loop, `with`, lambda, nested definition, comprehension or walrus; its only `if` is the leaf-bound guard and its only loop is the coordinate listing, verbatim; every statement it evaluates for effect is a `print` from a fixed argument allow-list; its status line must be the proof's own verdict; and the four final assertions must be its last statements. `certify` and `main` must each be defined exactly once at module level and never rebound. Counting calls accepted `result = certify() if False else CertificateResult(True, ...)`, a module-level `certify = lambda: ...`, a shadowing second `def certify`, `print("status:", "CERTIFIED"); return` before the call, and `result = certify()` followed by `result = CertificateResult(True, ...)`; all five ran to exit code 0 printing `status: CERTIFIED`, four of them in under 0.03 seconds with `splits: 0` where the real certifier reports 3645.
- The historical and saved replay checks read the stored logs through the same proof-output contract as a live run. Setting `minimum_leaf_lower_bound_decimal` to `0` in a stored log and regenerating the manifest was accepted, and so was `splits: nonsense` with `maximum_depth: -1` once the same strings were written into the record, the per-job metadata, the aggregate CSV and the regenerated result tables. The four measurement columns of the result tables and the `splits` and `maximum_depth` fields of every replay record are now required to be canonical non-negative integers.
- `QUICK_NS` moved to `certificate_lib`, so the writer and the validator share one definition of what a quick replay covers.
- The test suite creates one real quick replay per process instead of one per test class, and each mutation test copies it. 103 tests now run in about 158 seconds, where 77 tests previously took about 305; no check was removed or skipped to achieve that. Round 4 brings the suite to 160 tests in about 123 seconds.
- Tests that needed a stand-in certifier now plant a real one — a single light at the centre of the square, which certifies immediately — instead of a script that prints a status and nothing else. Such a script is no longer a successful run, which is the point of the proof-output contract; the tests that used it as their positive case would otherwise have been asserting the defect.
- Both replay scripts refuse to start under `python -O` or `PYTHONOPTIMIZE`, which would disable the `assert` statements each certifier uses to re-check its own certificate, and remove `PYTHONOPTIMIZE` from the child environment.
- `.github/workflows/smoke-test.yml` also runs the unit tests, the semantic consistency check, the generator check and the upper witness audit.
- `.github/workflows/full-replay.yml` runs on `workflow_dispatch`, `workflow_call`, a weekly schedule and every push and pull request, with no `paths:` filter: a workflow skipped by a path filter reports no status, and a required check that is never reported leaves a pull request pending. The job is self-contained — unit tests, every static check, the replay and the replay-output validator — so it can be the single required check. CI output goes to a scratch directory and never overwrites `evidence/full-cleanroom-replay/`; the artifact upload warns rather than errors on an empty directory so it cannot bury the real failure.
- All `uses:` references are pinned to full 40-character commit SHAs.
- `MANIFEST_POLICY.json` includes `tests` in the integrity manifest.
